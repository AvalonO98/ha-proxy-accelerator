      DAEMON_JSON 怎么用? (HAOS 与 Supervised 不同)
      
    
        
    Supervised / Debian 主机: 把上面的 registry-mirrors 写入 /etc/docker/daemon.json,
           然后 sudo systemctl restart docker。之后 docker pull 与 Supervisor 安装
           Docker Hub 镜像(add-on 商店里的纯 hub 镜像)都会先试加速源。
    
        
    HAOS(系统盘只读): HAOS 上 /etc/docker/daemon.json 无法直接改。社区常用「udev 规则」
           在开机时把配置写进去。点击「复制 HAOS 持久化脚本」, 把脚本内容通过官方 SSH & Web Terminal 写入
           /etc/udev/rules.d/99-docker-mirror.rules 即可(不会随系统升级丢失)。
           写入后 重启主机 生效。
    
        
    注意: 若你的网络能直连 Docker Hub, 镜像源收益有限且失效频繁 —— 面板的「可达性检测」
           会标红不可用的源, 请选绿点延迟最低的 1~2 个。
    
      
    
    
    
  
    

  
  
    
    
    ③ GHCR 加速 — Home Assistant 内核更新 core / supervisor / add-on 镜像均来自 ghcr.io
    
    
    
      
      
    
        
    可达性检测 
    
        
      
      
      
    
      
    
      
      
      
    
      
    
      
    
      
      原理与前提: 为什么 HA 内核更新需要 dockerd 走代理, 而不是 registry-mirrors
      
      
        
      Supervisor 拉取内核镜像的地址写死为 ghcr.io/home-assistant/…。
           Docker 的 registry-mirrors 只对 Docker Hub 生效, 对 ghcr.io 无效。
           因此让「HA 更新」变快只有两条路:
      
        
        
          
      • a) 给 dockerd 配 HTTP(S) 代理(Supervised 上最简单): 上方按钮生成
              /etc/systemd/system/docker.service.d/http-proxy.conf 内容, 其中代理指向本插件的
              入口(如 http://<HA主机IP>:8899)。之后 dockerd 拉 ghcr 与 Hub 都走你的上游。
              前提: 本插件「代理入口总开关」需打开且上游可用; 白名单已默认放行 ghcr.io/docker.io。
        • 
          
      • b) HAOS 开机脚本注入 daemon.json/代理: HAOS 上 docker 由系统管理, 采用与 ② 相同的
              udev 持久化写法(点击上方按钮生成), 把 HTTP_PROXY/HTTPS_PROXY 注入
              docker 服务环境再重启 docker。
        • 
        
      
        
      两条路都属于「宿主侧配置」, add-on 沙箱无法代写 —— 这是 Home Assistant 的安全边界。
           本面板负责: 生成可直接粘贴的配置、检测镜像/链路可用性、以及开关你的代理入口。
